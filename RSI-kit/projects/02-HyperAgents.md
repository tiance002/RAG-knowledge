# HyperAgents · 项目解析

任务能力与提出改进的能力共同演化；主实验的外层选择仍固定。

## 核心机制

区分处理业务问题的任务程序与提出修改的元程序。两者都能成为可编辑对象时，一代候选也可能改变下一代怎样查日志和提案。需要分别记录两种源码身份。

## 原项目怎样运行

|环节|实现思路|使用条件或边界|
|---|---|---|
|定位与贡献|研究框架；任务 Agent 与元 Agent|任务能力与提出改进的能力共同演化；主实验的外层选择仍固定。|
|可修改对象|任务 Agent 和可编辑的元 Agent。|主实验父代选择机制固定；模型权重冻结，不能理解成全系统无限自改。|
|如何发现问题|元 Agent 可依据代码和历史结果修改任务 Agent 或元 Agent。|需要可执行的代码环境、既有结果和迭代预算。|
|父代与经验|主实验按表现与有效后代数量进行概率选择。|归档任务 Agent 与元 Agent 的候选；评测后可再选其为父代。|
|如何判断效果|任务得分及固定预算下改进能力比较。|元 Agent 可修改并不保证改进可靠；开销和评测误差不可忽略。|

## 在 RAG-knowledge 中怎样试

同一组历史失败、相同预算，比较两种提案器哪个能更常提出可验证修正。先冻结失败集、允许修改范围、评测器和停止条件。

## 接入时机与成本

排在后期。只有一次已知故障时无法判断元策略的泛化；若能修改评分函数，分数变化也无法归因。
