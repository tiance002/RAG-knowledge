# ECS 隔离监控的本机服务配置

Docker Hub 在本次 ECS 上不可用；实际运行的是隔离解包的 Ubuntu 官方源 Prometheus `2.45.3+ds-2ubuntu0.3`、Node Exporter `1.7.0-1ubuntu0.3` 和 Grafana OSS `11.2.0`。Grafana `.deb` 经阿里云镜像下载并与 Grafana 官方 SHA-256 比对；两个 Ubuntu 包与本机可信 APT 元数据的 SHA-256 比对。此目录中的 systemd 文件是当前 ECS 配置记录，含 ECS 绝对路径，不是可直接移植的安装程序。

三个服务绑定 `127.0.0.1` 的 19090、19100、13000 端口，并设置资源上限和自动重启。Prometheus 保留 24 小时或 512 MB；Grafana 密码由隔离服务配置从 ECS 本地文件读取，不在本目录保存。可通过 SSH 隧道访问 Grafana；该目录不包含凭据。

采集的应用目标 `127.0.0.1:18200` 只用于临时隔离应用。正式 RAG 仍在 8200，未启用 `/metrics`，不能将隔离测试数据视为正式服务指标。临时应用停止后该目标会显示 `down`。数据库、Redis、任务等待队列、Agent 正确补救率及价格等没有可靠数据的指标不能推定为零。

本次隔离测试的 Prometheus 查询曾返回约 0.089 QPS、P95 0.0475 秒、HTTP 4xx/5xx 比例 12.5%，以及 SSE DONE=2、FAILED=2。这是少量受控请求（含人为制造的 404 和模拟检索故障），不是性能基线。P95 为直方图桶插值。服务顺序重启后配置和已有 SSE 计数保留；主机重启恢复尚未验证。当前 systemd 单元以 root 运行，应在后续收紧运行用户与文件权限。
