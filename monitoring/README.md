# Isolated monitoring (prepared, not deployed)

This independent Compose project uses named volumes and Linux host networking. It does not edit, restart, or attach to production services. Prometheus and Grafana bind to ECS loopback ports 19090 and 13000; use an SSH tunnel for access. Check those ports and host resources before starting. Node exporter listens on 127.0.0.1:19100 only and reads host `/proc`, `/sys`, and filesystem metadata using read-only mounts. It has no shell-based container health check; Prometheus `up{job="node"}` checks scrape availability.

Create `secrets/grafana_admin_password` locally with a strong password and owner-only permissions before deployment; never commit or print it. Grafana initializes its administrator password on first use of a fresh volume; changing the secret file later does not reset an existing database password. This directory ignores the secret and `.env`. The default admin username is `admin`.

Prometheus scrapes `127.0.0.1:18200/metrics`, reserved exclusively for a separately authorized isolated API. That endpoint is not currently established by this configuration. Verify its identity and contract before starting monitoring; never bind production to this target. Host networking allows the scrape to reach a loopback-only API; it is supported by Docker Engine on the Linux ECS host. All three processes explicitly bind loopback, but any local host process can access these endpoints. Host networking shares the host network namespace and has less network isolation than a bridge; port collisions or later listener configuration changes could affect existing services. Check all four ports and exact target identity before launch. No application or model request is issued by this configuration; scraping a target sends HTTP GETs.

Retention is limited to 24 hours and 512 MB TSDB blocks; WAL, compaction, and Grafana data add overhead, so these are not a hard disk quota. Container resource limits are ceilings, not capacity guarantees. Pin tags should be verified against image digests and platform before deployment. Dashboard panels query the local source instrumentation schema when enabled; a missing series is not evidence of zero. Queue depth, quality, citation correctness and cost remain unavailable. Token panels show only provider-reported usage, when emitted. `up` is scrape availability only. Existing Langfuse traces and evaluation data are separate and not ingested here.

Configuration validation: `docker compose -f monitoring/compose.yaml config --quiet`. Start, health and functional verification are NOT RUN. Prometheus and Grafana health checks depend on image-supplied `wget`; verify on the actual pinned images before relying on them. No alert delivery is configured.
