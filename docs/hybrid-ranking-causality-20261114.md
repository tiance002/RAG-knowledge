# 检索排序差异：固定向量与 A/B 向量复核

2026-11-14。独立只读检查已下载的真实 ECS 产物：`var/hybrid-followup-20261114/followup/ranking-control/` 与 `ranking-serial-ab/`。本次只写本文，没有代码、ECS 操作、模型调用或新增测试。

**本轮可以确认：固定同一查询向量时，所检查的串行/并行读取结果一致；改变已捕获的查询向量，可以改变相似度，并在一个问题上造成排序反转。不能把“序列化 hash 不同”一律说成“排名不同”，也不能据此把此前七对差异全部归因于 embedding。**

## 1. 固定向量：24 次检索、36 个比较全部一致

先对六个问题各实际请求两次 `BAAI/bge-m3` embedding，维度均为 1024，再固定各题第一次返回的向量，交替执行两次 serial、两次 parallel。每题四次检索有六个两两比较，共 24 次检索、36 个比较。

| 问题 | 固定向量下的六个比较 | 两次实际 embedding 的完整向量 hash |
|---|---|---|
| `terra-ecs-b1-024` | 6/6 一致 | 相同 |
| `terra-ecs-b2-030` | 6/6 一致 | 不同 |
| `terra-ecs-b1-006` | 6/6 一致 | 相同 |
| `terra-ecs-b1-030` | 6/6 一致 | 相同 |
| `terra-ecs-b1-008` | 6/6 一致 | 不同 |
| `qst_0044` | 6/6 一致 | 相同 |

“一致”逐项覆盖实际 Chroma page 的 ID/距离、有效性过滤后的完整 vector/lexical RRF 输入、完整融合记录及最终 `RetrievalService.search()` 交付记录。后者位于本地 query expansion、RRF、enrichment/检索去重之后，**父块/邻居 context expansion 之前**。

已重新计算全部记录 hash，并确认每次 injection、目标查询和 Chroma page 使用的都是对应的固定向量。没有只信任 summary 中的布尔值。

## 2. 零新增模型请求的 serial A/B

只对两题向量 hash 不同的情况，复用已保存的第一次向量 A、第二次向量 B，各执行一次 serial 检索，共四次。新增 embedding method 调用和 HTTP 发送均为 **0**；整个实验累计仍是 **12 次 embedding、28 次检索**。

两题的 replay A 在五个捕获阶段均与此前同向量的 S1 完全一致；A/B 的 lexical RRF 输入也保持一致。原实验全部 **51 个产物**的 hash 仍与 replay manifest 的快照相符。

下表对相同 chunk ID 比较字段，避免把位置变化与数值变化混为一谈：

| A/B 观察 | `terra-ecs-b2-030` | `terra-ecs-b1-008` |
|---|---:|---:|
| 最终 Top-10 ID 集合 | 相同 | 相同 |
| 最终有序 ID 序列 | **相同** | **不同：4/5、8/9 互换** |
| `vector_score` 不同的 ID 数 | 10/10 | 10/10 |
| 归一化融合 `score` 不同的 ID 数 | 0/10 | 4/10 |
| `rrf_score` / `vector_rank` 不同的 ID 数 | 0/10 | 4/10 |
| `bm25_score` / `bm25_rank` 变化 | 无 | 无 |
| 对应正文 `content_sha256` 变化 | 无 | 无 |

### b2-030：hash 不同，但交付 Top-10 排名没有变化

A/B 所有十个 `vector_score` 都不同，导致最终序列化记录 hash 不同；但最终十个 ID 的顺序、RRF 分数、归一化融合分数和正文 hash 均相同。完整融合池的较低排名可以变化，不能把这一点混同为已交付 Top-10 变动。本次没有复现该题历史对照中的 Top-10 成员替换。

### b1-008：查询向量变化足以反转同一对切片的相对顺序

| chunk ID | A 向量分数 / 最终名次 | B 向量分数 / 最终名次 |
|---|---|---|
| `9ce53761-f89c-49d0-8da9-d85736963363` | 0.40298210 / 4 | 0.40238090 / 5 |
| `2aa46a92-c206-41c5-b042-b5b06e0bc596` | 0.40239870 / 5 | 0.40289460 / 4 |
| `41bdb045-a6e3-4ad0-abde-50c861de6f43` | 0.39543960 / 8 | 0.39479960 / 9 |
| `056acc23-e31f-48b3-8c6d-1ab14f30487e` | 0.39520750 / 9 | 0.39617250 / 8 |

这些结果均为 serial，未切换成 parallel；改变的是注入的已捕获 A/B 查询向量。4/5 的两个切片正是历史 serial/parallel 差异中发生相对顺序反转的那一对，说明查询向量的变化**具备造成这种反转的能力**。两臂 ID 集合和对应正文不变；不能声称复现了历史七对的完整输出或全部边界替换。

## 3. 因果结论及边界

- **已验证**：本次六题固定同一查询向量的 24 次读取，在捕获的全部检索阶段无串行/并行差异；没有发现该受控输入下的 RRF 稳定排序违约。
- **已验证**：相同问题的实际 embedding 返回在 2/6 题出现数值差异；其中 b1-008 的 A/B 向量在相同 serial 路径下引起分数及顺序反转，b2-030 只改变了已交付 Top-10 的向量分数。
- **仍不能确定**：历史七个差异配对没有保存实际查询向量，无法逐对证明它们由 embedding 变化造成，不能排除未观测的 ANN/数值或环境因素。当前结果也不能证明所有问题、索引和并发水平都逐字节可重复。
