## A. 持久化与接口

| 场景 | 实际执行与预期 |
|---|---|
| 四表初始化 | 对临时库调用现有 init_db，两次启动均可；原业务表数量/数据不变；构造 Store 本身不建表 |
| 会话 CRUD | 创建 SELECTED、ALL_ENABLED，分页、修改 title/model；范围参数不能偷换为空后全库 |
| revision | 两次相同 revision 修改只能一次生效；旧版本 409，不覆盖前一次结果 |
| 幂等 | 同 session/request_id/question 重复提交，只产生一次产品流/模型请求；改变 question 返回 409 |
| 回执复读 | 模型配置被删除、会话范围不可用后，旧 request_id 仍可读取原回执，不再调用模型 |
| 同会话并发 | 两个同时请求最多一个新轮次取得所有权；文件型 SQLite 实测，不只内存库 |
| 不同会话 | 两会话可以并行，来源及回答不串到另一会话 |
| 租约 | 超时轮次为 UNKNOWN；旧 token 不能 finish；重启不自动重发；取消后保留已发送部分 |
| 终态 | COMPLETED、TRUNCATED、EMPTY、UNKNOWN、FAILED、NOT_RUN 原样保存；固定兜底不能伪装模型生成成功 |
| 提交失败 | 终态写库失败时客户端不得收到持久化成功 done；保留错误与原请求身份 |

同时核对 SSE turn_started 的 session_id/turn_id/revision，终态 session_revision 必须等于数据库实际值。客户端断线通过 GET 轮次恢复，不重新 POST 生成。

## B. 历史窗口与实际模型请求

构造六轮公开小型会话，后端最大历史设置为 2；第三至第五轮包含失败/截断，不能跳过它们而把更早成功轮次补进来。检查实际查询理解和最终生成 messages：只允许最近两个用户轮次加本轮；失败半句不能作为助手事实背景。改变窗口为 1、5 重复边界检查，不新增不必要的全量测试。

普通和 Agent 都执行以下三个业务样例；记录问题、预期事实、实际 messages、回答、来源及请求数：

1. 项目报告 → 另一主题 → 明确回指“前面运输项目报告”的项目经理。该题必须明确对象，不能根据评分器隐藏 depends_on_turns 要求模型猜歧义。
2. 前轮三种封闭运输方式 → 本轮问排除罐车还剩几种。当前检索未召回原文时，经过来源核验的历史条款应进入实际请求，并有本轮引用编号。
3. 与历史来源无关的新问题。不能把旧资料强行加入。

查询理解关闭/开启分别核对当前配置，不能把配置信号当实际改写已完成。以记录到的理解输出和客户端请求为准。

## D. 浏览器迁移

开始前读取并导出原 `rag-workspace.chat-history.v1` 的原始字节。用已有浏览器真实交互验证：

1. 旧会话仍显示，导出 JSON 与原字符串完全一致。
2. 导入后刷新，从后端读取对应历史和引用。
3. 相同导入两次，无重复；同旧 ID 改一条消息，形成独立副本，不覆盖第一份。
4. 混合有效会话、损坏会话、不成对消息；坏项有 index/error，有效项可导入；所有原文仍在浏览器备份和相应导入元数据中。
5. 导入引用默认 UNKNOWN；只有当前来源核验通过才进入新上下文。
6. 同页重载、直接 URL、会话数超过 100、轮次超过 50、断线、取消与页面切换。
7. 用 DevTools 检查新提问请求，只有 question/client_request_id/expected_revision，没有 messages/citations/客户端系统提示。
8. 服务端不可用时错误可见，不悄悄写回旧 key 或生成第二份离线新历史。

结束后再次读取旧 localStorage 并比较哈希。浏览器渲染验证单独报告，不能由 tsc 代替。
