日期 2026-11-03。本轮交付实验设计，各候选状态均为 **NOT RUN**。下表的题数、预算和停止条件是下一轮的实验上限，不是已有结果或模型调用授权。

## 共用基线与执行方法

1. 本轮起点为 `57f9972b8477b0c4aaf7fac329b911420fafc95e`，本轮修复尚未提交。以下基线指**经复核后的当前工作树**。开跑前记录 HEAD、`git diff --binary HEAD` 的 SHA-256、相关未跟踪源码/测试 SHA-256、环境与依赖版本。只记录 SHA 不能替代保存可恢复的补丁。每个候选均由同一份冻结基线派生，不把前一个实验的胜者自动带入下一个。
2. 从已有获准的冻结样本按**文档和追问会话**分开发集、留出集。在查看候选效果前冻结 qid、Gold 来源及字段、文档/索引哈希、题组、剔除规则和问题版本。已有路由拟合样本单列。若没有独立文档则标记探索性。冻结 Prompt、模型及参数、检索范围、融合权重、阈值、输出预算和候选截断位置；目标变量除外。
3. 优先只读复用索引、分阶段候选及模型输入，按 `run_id/candidate_id` 隔离缓存、结果和写入；需要重建时，仅在临时目录顺序处理所需文件。共享数据库、索引、Gold 和历史账本不得写入。优先用 SQL 内存库、临时目录与相同测试替身。
4. 每题保存基线和候选的实际输入身份、排序、原始分数类型、去重理由、证据正文或授权引用、字段/单位/位置、送达内容哈希及已知成本。只以相同输入身份配对。保存失败和分母，区分 PARTIAL、FAIL、UNKNOWN 和 NOT_RUN。HTTP 200、页码命中或引用编号存在均不能代替事实支持。核心回答按 Gold 要点覆盖核对，等义表达可接受。对有争议的问题统一提交人工复核。
5. 证据覆盖率 = 已送达的必要事实数 / 有可靠定位的必要事实数，同时报告全部必要事实送达的题数 / 可判定题数。不同 chunk ID 指向同一原文时按来源和正文对齐。报告候选新增/丢失及后续恢复。答案质量分母、截止时间、有效耗时样本和未返回槽位另计。费用无可信账单时为 UNKNOWN。
6. 下表每一行预算均为零真实外部调用。输入、缓存缺失或必须新发请求时记 BLOCKED，列出调用预算另审；不重试未知历史请求。不因单处呈现格式差异追加规则。任意跨库、破坏共享数据或调用越界，立即停止该候选并保留记录。
