## 检索状态和代码范围

`retrieval.py` 记录 SUCCESS、NO_RESULTS、RETRIEVAL_ERROR、UNKNOWN；当一路失败而不能排除遗漏时保守 UNKNOWN，正常双路空候选不再在新事件中标成实际故障。沿用原检索回退和返回值，原业务日志仍可能使用“检索失败”措辞。`agent_workflow.py` 只有有候选且评分格式有效、分数低于既定 0.8 才观测 LOW_RELEVANCE；异常或格式错误的默认分不强判低相关。未更改原 Agent 分数解析和阈值。`main.py` 正常关闭时调用 fail-open 的 SDK flush。`observability.py` 新增 event_id 与非阻断刷新；服务不可用不阻断业务的单元测试通过。

历史空库负例发生于上述新状态埋点之前，不能反填它的 NO_RESULTS/RETRIEVAL_ERROR。当前系统仍可能把检索错误转成无结果供 Agent 消费，应独立修复并验证，不能视为已由观测解决。
