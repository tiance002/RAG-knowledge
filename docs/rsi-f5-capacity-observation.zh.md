# F5 容量观测和 Provider 限额

新增容量分配和原子发布模块。控制端先按写入预测检查 20% 磁盘余量，然后取内存、数据库、Provider、可预留预算、Judge 队列及全局 12 的最小值，再按冻结顺序分配到各臂。发布文件绑定 panel 和执行阶段。缺少观测、超期或阶段不一致时，问答入口停止新派发。新的 DEV200 本地入口复用 DEV20/60 的容量检查、逐题保留和结算明确才补发逻辑。容量为零时，入口在读取凭据前退出，已运行的问答则按已有回执规则保存。DEV200 仍需完成跨进程续跑验证。

本地隔离 Provider 账本在既有 SQLite 记账事务中核对相同模型的在途记录。四笔仍处于 pending 时，第五笔不会写入回执或记账。结算不明的账本记录保留保守金额。用多个独立 SQLite 连接并发验证了四笔上限、拒绝第五码号以及完成一笔后允许补充。

本地观测器支持从固定配置的两个账本模式只读采集。它验证记录摘要、行数和金额边界，再计算预算和模型在途余量。ECS 与本地 Judge 各自保留现有账本。数据库可承载并发、Provider 剩余速率及 Judge 积压仍需同阶段、30 秒内的独立反馈，发布器对缺项安全停派。跨主机持续汇集和实际并发压测尚未执行，未在 ECS 安装发布器。
