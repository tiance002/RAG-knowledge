## S1：契约、执行与恢复

`ExecutionEvidence` 由宿主执行配置产生，不能从捕获中自报的模式选择。真实证据绑定受信适配器、业务源码归档和基线、worker、配置原始字节及规范形式、输入、镜像、固定运行时及捕获哈希；prepare 与两臂需要一致环境。运行时版本变更需要新的政策版本，不从第一次捕获自动信任。

数学成功与真实资格分开：合成测试可覆盖 ADOPT 数学分支，仍有 `real_eligible=false`；独立核查成功使用 `CONTROL_VERIFIED`，经验账本与资格池均有模式隔离，不能重开为真实账本。真实执行证明也不等于真实业务评测合格，来源、事实覆盖与独立性仍需各自验证。

旧 v2.2 回执和单候选归档不被改写成 v2.3 证据。新版真实准入缺少所需回执、完整家族或资格绑定时停止，历史未定类型记录保留但不自动升级。这会使旧基线不能直接用于新冻结实验；需新的完整资格或明确的迁移审查。

完成轮次恢复覆盖声明过的运行时 `rsik` 模块及 RSI 入口/依赖脚本清单，并复算实际输入与裁决。外部依赖和业务归档另由执行证据绑定；不宣称能检测任意操作系统或外部系统变化。恢复不发送模型请求，也不重新运行容器。

## S2：经验闭环与角色版本

`VerifiedCandidateEvidence` 从训练完整家族、核查回执和不可变完成事件重新构建资格，同时核对候选/父代、代码/配置、三个核查套件和可信锚点比较。提示词只有代码、兼容性、聚合数和不透明引用；没有核查题目、答案、来源短句或私有来源 ID。

当前新增有限动作 `REUSE_VERIFIED_SELECTOR`，只描述确切代码哈希在指定兼容范围内的已验证关联。它不自动推导一般算法规则，也不声称某条经验导致成功。Curator 仍只能提出 Delta；动作、证据引用、适用格式和兼容性均由确定性代码约束。训练阶段不会激活未核查经验。

事件链连接匹配、引用、使用、训练采纳、独立核查、失效和隔离；计数由事件投影生成。幂等键绑定候选/证据版本/事件及经验引用，恢复使用已有模型响应，不重复调用或计数。候选隔离会隔离其支持的经验、排除相关结果；未采纳和基础设施失败不会制造 harmful。

`ExperienceSession` 固定初始经验内容和 event frontier，受控学习事务才可推进 frontier；外部插入、删除或修改会在下一次请求前停止。未完成学习事务要求核对已有证据，不盲目接受事件尾部。每次 OpenAI 请求额外记录实际经验内容 ID、frontier、提示词哈希、角色版本、模型、接缝和请求配置哈希。

保留 Diagnosis、三个独立 Proposer、Curator、Meta。新 `query-k3-dependency/v1` 的第三角色为 `P3_DEPENDENCY`，研究跨成员依赖、邻接保留和保守回退；旧 `legacy/v1` 的 `P3_ORDER` 仍要求选中序列完全不变。宿主明确登记实际角色与固定统计槽的映射，保存模型原始提案和归一后的统计槽提案，不暗改旧角色。主路径默认 parallel/K3；K1 仅作比较组。所有静态合格实例独立回放，重复补丁也保留；另报规范化 AST 的独立策略数。

完整合成控制覆盖“引用经验→候选四套件回放→家族裁决→独立核查→可信 Delta→事件统计→下一轮 Diagnosis 读取”，以及重放不重复计数、兼容性拒绝、失效隔离和外部经验注入停止。捕获与模型替身均明确标记，不能据此宣称真实执行或真实收益。
