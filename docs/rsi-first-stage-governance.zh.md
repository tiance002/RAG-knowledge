# RSI 第一阶段授权与 Git 交付

本文件将用户的补充指令纳入 `02_Codex_Goal_Mode_总指令.md` 的 F0–F5 约束。与原指令冲突时按本文件执行。工程任务的修改授权、RSI 候选可以修改的范围、真实模型和受限数据授权是独立事项。

## 组件修改权限

| 层级 | 当前范围与行为 |
| --- | --- |
| L1 已授权 | Context Selection 仅限现有已审查的 `select_member_indices` AST 接缝、受控配置与隔离执行。已有 Prompt 及参数机制只能在原已审范围内运行；F2 核对完整 Provider 消息、质量/Token 接线与参数有效配置后，记录实际可执行的范围。支持候选生成、隔离测试、授权评测与结果记忆。 |
| L2 待开放 | ContextBuilder、Retrieval/BM25、Rerank 及其他尚未审查的业务算法，仅分析、提出假设、生成草案和静态检查。不得自动应用、运行超出授权的候选 Patch。旧质量 Registry 的 workflow scope 不是本阶段授权入口。 |
| L3 保护 | 保护 RSI 裁决和采纳硬门、授权与安全、预算、证据与独立验证、EventLog 哈希链及核心恢复、Git 发布权限和生产环境控制。RSI 可记录诊断和人工修复建议。 |

组件从 L2 升级为 L1，先形成可审查记录，明确允许修改的文件、函数和参数，列出输入输出及依赖契约，并核对单元测试、集成测试、全链路评测接线、隔离执行、失败恢复及变更前后的可追溯证据。用户授权 Codex 根据这些证据决定是否开放具体接缝。Codex 须记录通过的准入项、授权粒度和验证回执。证据不足的接缝继续按 L2 处理。组件按证据成熟度推进，模型提案和 Handbook 经验无权变更授权。ContextBuilder 要验证事实和来源保留。Retrieval/BM25 要验证 Recall、Precision、MRR 和候选身份。Rerank 要验证排序、候选保留、延迟和答案质量。

## Git 交付与人工边界

Codex 对已获授权且完成验证的候选检查资格和独立核查，确认正式版本基线，从该版本建立隔离分支，落实明确的候选改动、运行所需回归、提交、推送及创建或更新本任务 PR。现有 RSI 工作树与正式业务树不同，审查 PR 只带与候选对应的改动。

PR 写明问题与来源、组件及文件/函数、前后行为、Candidate ID 和 Parent ID、基线与候选提交、各项质量和效率变化、退化与权衡、输入/输出 Token、单元/集成/全链路结果、独立核查、限制和回滚方式。工程治理或审计提交没有候选身份时，按实际类型记 `N/A`。未测的数据明确记 `UNKNOWN` 或 `NOT_RUN`。

用户保有 main 的评审和合并权。Codex 可以根据 Review 修复和重测，不能自行批准、绕过评审、合并 main、删除正式分支或部署 ECS。部署由用户单独决定。PR 验证失败须保留候选和回执。已经合并的回归可提供 Revert PR，保留原提交并由用户审查决定。

交付复用 Candidate Registry、Experiment Ledger、独立验证、Git 和 PR。PromotionSandbox 只保留既有隔离测试用途。无需 Release Package、独立候选或发布数据库、生产 Promotion、发布 Agent、部署调度器或企业审批流。

## F0–F5 补充验收

| 阶段 | 必核项 |
| --- | --- |
| F0 | 记录 L1、L2、L3 实际权限，区分当前 RSI 工作树与正式版本。 |
| F1 | 逐候选绑定代码、有效配置、实际 Prompt、评测及运行版本；缺测和缺绑定如实展示。日志观测修复不开放算法修改授权。 |
| F2 | Prompt、参数、代码执行器分别执行授权限制，验证越权拒绝。 |
| F3 | 父代需满足当前目标及执行资格；排名与留档不授权修改，也不替代独立核查。 |
| F4 | 反思搜索及经验均不能扩展执行权限。 |
| F5 | 三类候选完成受控验证，至少一个代表性的受限业务代码修复基于正确正式版本形成可复现、可回滚的审查 PR。 |

与原阶段约束的处理：隔离、真实调用审批、数据资格、阶段提交与全量回归继续生效；原文的模拟 Promotion 仍只用于离线验证；产生代码正式交付时直接走 Git PR，由用户合并，执行完验证或合并均不会触发部署。
