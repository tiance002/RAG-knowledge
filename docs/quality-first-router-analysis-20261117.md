# GLM 正式绑定与质量优先路由分析

日期：2026-11-17。主分析：6.1sol xhigh；配置和数据核验、回归审查：6luna；规则实现：6.1sol medium。

## 目标与实际配置

第一优先级：尽量把 Qwen 部分正确或错误、GLM 能完全答对的请求交给 GLM。第二优先级：两者均不能完全答对时，尽量交给 Qwen。允许增加 GLM 使用，不以压低 expensive 比例为主要目标。

核对发现，正式 ECS API 原来没有路由环境变量，实际模式为 OFF。此前 300 题的动态路由发生在独立评测服务，不能当作正式服务已启用路由。代码内默认 expensive 名称虽为 GLM，但缺少正式绑定，单改名称不会让真实请求切换。

现在本地和 ECS 使用相同的显式配置：

| 项目 | 配置 |
| --- | --- |
| 模式 | `DYNAMIC` |
| 规则 | `QUALITY_FIRST_V3` |
| cheap | `Qwen/Qwen3.5-4B` |
| expensive | `zai-org/GLM-5.3-Flash` |
| expensive LLM 绑定 | `c50ba971-a07f-5f7e-a4e0-7965d489db4b` |
| 两角色 thinking 请求参数 | `false`；供应商仍可能报告 reasoning tokens，不能据此宣称实际推理关闭 |
| 自动质量重试 | 关闭；本轮不额外调用模型做语义判错 |

保留 Qwen 全局默认、旧 Xing 模型记录及 GLM 的 VLM 图片解析绑定。新增独立 GLM LLM 绑定，未把 VLM 改成 LLM。凭据沿用既有服务配置，未写入报告或路由文件。

`config/model-router.env` 为两端的运行配置，已排除 Git；启动时仅加载允许的路由键，进程环境优先，禁止变量插值和凭据字段。正式配置不含题号、Gold、历史评分或答案。

## 数据与判定分母

1. 当前 44 题定向重答：只有 40 题此前实际由 Qwen 回答，其中 1 正确、32 部分正确、7 错误；另 4 题此前由 Xing 回答。原 expensive 选择组的 5 题不能全部当作原 Xing 回答。
2. 40 题 Qwen/GLM 对照：26 道 Qwen 未完全正确而 GLM 正确；13 道两者都未完全正确；1 道两者都正确。沿用已审查的严格 Gold/证据判定，完整旧供应商请求未全部保存，提示词存在重建，不能全部称单变量实验。
3. 40 题中 37 题有检索证据，可进入当前检索回答路由；另外 3 题原来直接回答，没有检索片段。其中 1 题为 GLM 可修正题，2 题两者均部分正确，单独保留其证据范围。
4. 历史 178 题同输入实验中，提取实际 Qwen 与 GLM 均完成、有模型身份和可评分结果的 115 题。逐题核验实际 messages 相同、输入哈希一致、输出哈希与既有评分一致。这批评分主要是核心答案，不与当前严格评分合并。
5. 最新 300 题中还有 256 题没有 GLM 对照结果；不能推断这些题全部适合 GLM，也不能推断全部适合 Qwen。

两批中有 7 个重复问题文本，且有上下文或判定差异，不能当作独立样本简单相加。所有标签均为既有评审，本轮没有用运行成功替代答案正确。

其中两道“累计项目成本”问法，在历史输入下两模型都错，在当前输入下 GLM 正确；另有数值精度题的历史核心判定与当前严格判定不同。因此，本轮不能把某个题型的旧失败固化成永远交给 Qwen，更不能只按题目文本解释全部差异。解析和检索证据变化、提示词重建、评分粒度和模型随机性都需要保留为独立因素。

## 为什么旧规则漏掉可修正题

旧规则把“任务难度估计”当作选择依据，但任务难度不等于换模型的收益。

在当前 26 道可修正题中，旧提取器的 T 均值为 0、J 均值约 0.019，而跨段/来源依赖 D 均值约 0.968、输入负荷 L 均值约 0.934。旧权重给 T/J 各 0.25，给 D/L 各 0.10，阈值 0.5。许多自然问法没有命中 `calculate/ratio/计算` 等词，即使需要正确处理单位、数字、对象归属，也很难越过阈值。

旧的多个通用词标记缺乏区分力：当前可修正题与两者都不完整的题都常含 `and`。不能把出现多个问题、上下文长或资料多直接视为 GLM 必胜，也不能把高难题全部升级就认为已优化。

当前 Qwen 的 39 道未完全正确题，按冻结题型分解如下；这些题型仅作离线诊断，未传给运行时路由：

| 题型 | 未完全正确题数 | GLM 修正为完全正确 | 两者仍未完全正确 |
| --- | ---: | ---: | ---: |
| 事实提取 | 19 | 15 | 4 |
| 数值计算 | 10 | 8 | 2 |
| 多跳推理 | 6 | 1 | 5 |
| 语义理解 | 2 | 0 | 2 |
| 无答案题 | 2 | 2 | 0 |

分层中的另一道数值题原本已正确，因此不计入表内 39 题。GLM 在部分事实提取题的提升，主要体现为选对主体、时间、单位和配套事实；无答案题的提升体现为不编造未给出的数值。多跳/操作流程题则常持续遗漏条件，证据缺失也不能通过换模型修复。

## 已实现规则

`QUALITY_FIRST_V3` 默认选择 GLM，不再要求多个稀疏关键词叠加后越过旧加权阈值。原分数仍记录供分析，但不伪装成成功概率。

以下任务优先交给 GLM，即使同时命中节省调用的规则：

- 派生数值运算：差额、比率、百分比、年份间隔、求和、加倍等。
- 对话对象与来源对齐：刚才、同一报告、该项目、前面题目、`its/that report/same/previous` 等。
- 关系和字段对应：分别、口径、对应、比较、`respectively/compare/difference` 等。

当没有以上优先风险时，以下两类允许留给 Qwen：

- 需要完整覆盖许多细节的操作流程：sequence、mitigations、preventative follow-ups、escalation path、rollback/disable path 等。
- 精确标识符读取：环境变量、分支名、邮件与 Slack 通道组合等。

这两类是当前数据中换模型收益偏低的任务家族，不是“两者一定答不对”的证明。其他可用检索证据请求默认交给 GLM。空证据、检索失败、固定模式及 OFF 回退仍优先，未制造证据绕过限制。

另补充独立的历史直接回答分支：仅在 `DYNAMIC + QUALITY_FIRST_V3`、确有当前问题之前的非空 assistant 历史、且属于派生数值运算时选择 GLM。它明确记录 `HISTORY_ONLY`、检索证据为 0，未改写成检索成功。没有历史的普通聊天和其他旧模式保持原有路径。新增调用仍检查总请求预算、限制生成长度、执行调用授权检查，并在成功或失败后关闭新建客户端。

## 离线回放结果与限制

| 数据范围 | 可修正题交给 GLM | 两者不完整题交给 Qwen | 新规则角色分布 |
| --- | ---: | ---: | --- |
| 当前 37 道可进入检索路由的 Qwen 对照 | **25/25** | **7/11** | GLM 30、Qwen 7 |
| 当前 40 道对照，含独立历史直接回答分支 | **26/26** | **8/13** | GLM 32、Qwen 8 |
| 历史 115 道同输入核心评分对照 | **7/7** | **0/11** | GLM 115、Qwen 0 |

当前 37 题按保存的模型输出回放，新规则选中的结果为 26 正确、10 部分正确、1 错误；全部选择已存 Qwen 输出时为 1 正确、29 部分正确、7 错误。这是定向难题样本的离线选择结果，不是总体正确率。

历史 115 题中，新规则选已存 GLM 输出后，完全正确从 Qwen 的 97 提升为 102；但其中 **2 题 Qwen 正确、GLM 部分正确**也被交给了 GLM。它们涉及影片产业归属和游戏版本比较。这是明确保留的反例，说明默认 GLM 同样可能损失个别题的完整度。

第二优先级尚不完善，尤其历史 11 道两者都不完整的题没有被节省规则区分出来。没有为了迎合已知标签，把报告哈希、题号、专名或缺失的 Gold 数值写进规则。`isolated-session8-v2-s1-t08` 由新增历史直接回答分支覆盖；三个直接回答记录中，两题选 GLM、一题保留 Qwen，对应 1 道可修正题被捕获、2 道持续部分正确题中 1 道留给 Qwen。此处是调用真实分支、替换绑定工厂为测试替身的离线选择检查，没有新增供应商调用，也没有声称检索补齐了证据。

当前标签已用于设计规则，不是盲测。历史来源存在重叠：150 个已有上下文按共享检索来源连接成 21 个组，最大组 50 题，其后 38、15 题；该关系仍不保证正文没有转载或重复。未做逐题随机切分并声称来源独立验证。尚需未参与规则设计、按独立原文分组的验证，才能判断泛化收益。

## 测试、部署与回滚

本地第一轮聚焦回归 180 项全部通过；历史分支适配后最终组合回归 **202 项全部通过，0 失败、0 跳过，7 条既有弃用警告**。第一次 167 项中发现 1 项实际缺陷：预算统计对 `None` 正文调用 `len(None)`，先于空证据路由拒绝而崩溃。已改为仅统计真实字符串正文，并新增 None/整数/字典回归。原失败日志保留。

本机正式配置启用后，少量旧测试假定默认策略仍为 WEIGHTED/原自动升级开关，导致读取真实运行配置的测试环境污染；保留失败记录后，最终测试子进程通过 `RAG_MODEL_ROUTER_ENV_FILE` 指向确认不存在的绝对路径来隔离配置，未关闭或修改本机正式路由文件，也未放宽测试断言。

ECS 首次隔离候选编译 4 个模块及 3 个无模型调用的规则检查通过。正式 API 在队列及连接空闲时加载文件，保留原代码和可执行回滚；历史直接回答适配为后续三个模块的增量变更，回滚清单追加原文件，不覆盖第一次回滚依据。数据库文件、切片、构建、知识库、全局设置范围哈希不变，原有模型记录哈希不变。没有复制完整数据库、语料、索引或虚拟环境。

正式请求验证与最终资源结果记录在同目录交付文件 `var/router-glm-20261117/live-audit.json` 和最终部署收据；不把 HTTP 200 当作正确答案。验证脚本首次使用错误 URL 得到 404，未触发供应商调用，原始记录保留后改用 OpenAPI 确认的 `/api/v1/chat/completions`。

首批四题真实接口验证均 HTTP 200、有非空回答、生成 COMPLETED、模型身份 MATCH，分别为 GLM/Qwen/Qwen/GLM。完整问答耗时 122.011、26.790、29.546、20.360 秒；不与此前仅回答模型调用耗时混比。第一题的观测明确显示 Qwen 查询改写约 68.10 秒、检索约 20.38 秒、GLM 最终生成约 32.55 秒；没有证据将其归因于冷启动。该题供应商报告 1,433 个 reasoning tokens，尽管请求参数为 false；此前冻结重答同题亦报告 2,789 个 reasoning tokens。不能承诺仅换最终路由就缩短改写和检索耗时。

第五题为历史直接回答路径的真实验证，发生在三个适配模块部署后：`isolated-session8-v2-s1-t08`，HTTP 200、GLM 模型身份 MATCH、`finish_reason=stop`，耗时 **10.263 秒**，核心回答 54,488.17 − 51,971.46 = **2,516.71 万元**，与冻结 Gold 一致。路由明确记录证据范围为历史、当前检索证据 0。回答重复了历史编号 `[6]`，本次没有新的检索引用，不能据此宣称引用映射已验证；本轮也未完整重评其余四题引用准确率。

最终七个生产模块与本地 SHA-256 一致；路由文件内容一致，原始字节差异仅为本机 CRLF / ECS LF，统一换行后哈希一致。首次直接比较原始字节未通过的校验记录已在最终收据说明，未将其归因为配置差异。

全部验证任务均退出码 0、systemd Result=success。正式 API 最终健康检查 200，解析与索引服务保持 inactive；未开启解析。验证时边界可用内存最低约 **2,030 MiB**，最后一次重启后约 **2,182 MiB**；这是请求边界采样，不是连续内存峰值监控。

临时详细观测在验证结束、空闲重启后关闭，正式 DYNAMIC/V3 配置保留，防止详细日志持续增长。62 个 ECS 原始证据文件已下载至本机 D 盘 `var/router-glm-20261117/ecs` 并逐一核对 SHA-256。保留原始请求、SSE、模型回执、首次 404 记录、原始详细日志和七模块回滚；删除候选目录和两份代码传输包约 289,081 字节，以及两端各 13,073,292 字节的临时证据传输包。

ECS 清理前可用 9,355,927,552 字节，删除候选后 9,356,255,232 字节；临时证据包删除前 9,344,155,648 字节、删除后 **9,357,230,080 字节（约 8.71 GiB）**。不同时间段的差额还包含其他运行写入，不能全部归因于本轮文件。必要证据约 54.6 MB，没有新增数据库或索引副本。收据见 `ecs/cleanup-receipt.json`、`ecs/transfer-cleanup-receipt.json` 和 `final-verification.json`。

## 交付文件与方法依据

分析参考了 [Langfuse 错误分析流程](https://langfuse.com/guides/cookbook/error-analysis-llm-applications)：先查看实际失败行为、区分原因，再分组统计并选择改进。本轮复用本地已有结果与评审，没有新建 Langfuse 数据集或要求用户重做既有标注。
