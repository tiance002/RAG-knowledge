# S3 评测准备与 S4 冻结实验计划（未启动）

S0–S2 只完成可信机制及接线。本文件为后续准备，不构成新真实实验或生产授权；当前准备清单未就绪。

## S3 来源与事实覆盖

1. 复用原始资料、冻结事实和已见失败，登记文档家族、来源版本、转载/衍生关系及哈希。来源字节不同不能单独证明知识独立。
2. 建立统一暴露账本：训练的四个套件、祖先候选已见材料、失败示例、所有已使用核查来源都登记。原核查集不重新包装成“新独立”来源。
3. 必要事实至少覆盖非 seed、跨成员关系、否定/条件、范围/单位/归属、多个独立来源和引用绑定。对每项提供原文位置与正/负控制，证明保留正确且丢失可检测。
4. 现有 seed 事实假设有明确版本。新题型不兼容时建立新的 fixture/evaluator adapter 与血统，原六文件、Gold 和旧断言保留；不能放宽事实要求迁就候选。
5. 双向 seed、同源备用问题和重复回放保留作压力控制，不扩大独立来源分母。AI 提议/自检与人工复核分别标记；高风险关系优先人工复核，争议保留 UNKNOWN。
6. 资料不足即记录覆盖缺口。S3 冻结清单需要来源家族分组、评测政策、暴露版本、独立核查使用规则和未决事实，不制造题目凑数。

## S4 对照、配置与预先分析

主体配置为 K3，保留六角色；成本优先使用 OpenAI Luna，仅符合既有编码失败条件时升级 Sol，禁用 Astra。K1 和冻结旧角色在同一修复后内核上作比较组，不恢复失效的 a1 计算收益。

每组计划三次独立重复，匹配初始父代、可见证据、模型、初始记忆与实际总费用额度。各组只累积自己的运行内学习事件，不能共享试验后经验。反馈改进、经验桥和新 P3 分版本；要归因作用需另做消融，不能把同时改变多项的一次结果归因于多代理。

冻结 implementation 清单、actual role profile、提示词、初始经验内容/event frontier、父代与完整家族、fixture/evaluator、随机/解码配置、账本和暴露版本。外部人工插入策略即使实验失效或形成新工程版本。恢复时只核对已有证据，未完成外部动作不盲目重做。

原累计 USD5 账本继续使用；计入 Diagnosis、三个 Proposer、Curator、Meta、格式修复、失败和 UNKNOWN。调用/轮次无数量上限，无预留，最后一次单调用可跨线。预算不是必须花完的目标。各比较组实际费用如何匹配及分析时点需在 S3 就绪记录中预先固定，缺项不得启动。

开发期 p 值为探索性。事前固定独立核查次数、分析时点、停止/复盘条件和重复核查规则；每次来源使用登记暴露。某提案弃权、无收益或格式失败不把 K3 改成 K1；证据身份不明、父代事实失败、裁决不一致、外部副作用不明和费用未知则停止可信边界之后的动作。

报告实际请求/费用、契约有效率、静态通过率、AST 独立策略与重复率、真实回放完成率、事实回归、NO_GAIN/OBSERVED/INCONCLUSIVE/基础设施故障、训练采纳和独立核查。零验证改进时每改进成本为 N/A，保留总支出。

通过上下文硬门后才准备隔离配对问答：固定问答模型、提示词、检索、解码及并发，平衡顺序并重复配对。逐题记录输入/输出 usage、答案正确性、遗漏、无依据陈述、引用、空/截断、首 token 和总时延；小样本不夸大 P95。字符、token、费用和延迟各自报告，质量争议保留 UNKNOWN。
