# RSI v2.3 S3 续作：覆盖收集、来源审计与连通性

本轮基于 PR #1 的 `2998638a22020e9fc731a258cb1819c6b396a6ba`，继续原 S2.1–S7 规范。入口已核对本地与远端相同；保留用户原有业务及前端改动。工程修复与合成控制不记入自主实验收益。六个保护文件、事实门、固定三槽 Holm 和统计阈值不变。

## 新增实现

- 为冻结 worker 的实际编号来源标题增加显式 `numbered-delivery/v1` 引用适配。旧 `explicit-citations/v1` 行为保留；不向真实捕获伪造 `citations` 字段。
- 覆盖负控制必须使指定目标原子缺失；其他原子缺失不能代替目标原子的失败。UNKNOWN 来源及不满足对应审查策略的来源不能贡献六类覆盖。
- 新增 `COVERAGE_COLLECTION`，仅允许 Capsule 执行预先审定的准备输入及登记的正负 worker/config。交付输入必须来自本次实际 prepare，禁止模型请求、父代资格、ADOPT 或 VERIFIED。正常阶段仍要求覆盖重算、真实回执及父代资格。
- 真实覆盖核查重读 prepare/positive/negative 回执、原始输入输出、配置、运行时、来源及快照指纹，绑定 collection plan、launch plan、run、完整 Capsule job 和执行序号。实际旧回执移植反例保留并被拒绝。
- 来源 fixture 的九项身份与实时暴露快照逐项连接。新文档别名继承全部历史暴露，UNKNOWN 共同依赖分量保留；别名不产生独立性或未见过的资格。
- 官方 API 默认直连；只有显式配置才使用本机 loopback HTTP 代理。保留 TLS 校验、官方端点和禁止重定向；实际模型边界绑定传输模式、代理摘要和 helper 摘要。禁止 Astra、Terra。
- Capsule 的断管不自动重发，远端结果保留 UNKNOWN；关闭失败不覆盖主异常，始终尝试保存本地日志。未获得真实删除确认时不宣称清理成功。

比较题要求分别保留两份原文的独立命题，不添加原文未声称的因果关系。负控制仅删除指定非种子成员，属于工程控制，不是模型提出的改进策略。

四份 fixture 各含相同的 20 个题源，复用原始文件的硬链接。主套件之外，query-conservative 明确为重复主问题控制；forward-seed 有 19 题改变、1 题保守回退；backward-seed 全部保守回退。后两种回退由固定窗口可达性及非种子必要性约束导致。不能把这些重复或回退报告为四套独立样本，也不能声称真正的查询改写和反向种子压力验收已完成。

主套件已完成一次新版本真实隔离收集：20 次 prepare、20 次正交付、20 次负交付，共 60 份执行回执；26 对指定原子的正负判定通过。实际命令退出 0，全部 worker 退出 0，容器移除和任务清理获得确认，本地 journal 已保存。此处通过的是执行与事实丢失控制。由于来源关系仍 UNKNOWN，六类的准入合格家族数均为 0，覆盖结论仍为 `BLOCKED_DATA`，没有产生 BASELINE_QUALIFIED、ADOPT 或 VERIFIED。

此前一次调用遗漏 SSH 用户名，在准备前被拒绝；更正后的旧 epoch 在第 5 题准备时 SSH 重置，关闭错误曾掩盖主异常。原始日志、前四题部分回执及未知状态完整保留，远端清点确认无任务容器，旧任务目录留作恢复。修复后使用新 epoch、新冻结计划和新目录完整重跑，未续接或补造旧运行的缺失回执。

本地文档归属不能替代上游文章 ID、版本、转载或派生关系。没有把不同 UUID、哈希、标题或低文本重叠率直接批准为独立家族；这些来源的上游家族与暴露不确定性保留。101 个导入身份均有暴露事件：60 个 DEV、41 个 CONTROL，并有 18 个已消耗 holdout 身份。历史导入自身仍标注不完整。

库存另有 11,599 个未出现在导入表中的唯一哈希，但“未登记”不等于“未暴露”，目前不能从中批准最终独立核查材料。未读取受限 FINAL/Gold 内容，没有改变权限。
