# 大文件父子切块：SQLite 与 Chroma 写入优化

日期：2026-11-12。本轮只修改本地项目，未操作 ECS 上正在运行的解析、Worker、数据库、索引、磁盘保护或内存限额；外部模型调用为 0。用户提供的 11738/11779 进度及云盘 I/O 数据作为背景，不冒充本轮重新测量结果。

## 实现与边界

| 文件 | 修改 |
|---|---|
| `backend/app/services/index_builds.py` | 原始切块 ID 按 500 个批量查询旧来源；保留同文件、正文、页码、内容类型完全一致才复用的条件。旧块按文件一次删除，新块按批 Core insert；保持原索引 STAGING 持久化、完整向量校验、所有权/generation 检查、原子发布与延迟清理。 |
| `backend/app/services/bm25.py` | 原本已有批量插入，未重复开发。词频与统计 JSON 使用紧凑编码；同文档频率净变化为零时保留原 JSON，避免无效编码。统计的计数与检索语义保持；增加 prepare/remove/replace 计时，以及统计 JSON 解码/编码时间、前后字节数、变化词数、子块和倒排条数。 |
| `backend/app/services/vector_store.py` | 单份文件的显式 `collection_operation` 复用同一个 Collection 句柄。每份文件仍执行新的 count/维度 query，保留 add/get 分批和完整向量、正文、元数据回读校验；不跨文件缓存维度结论，不在旧 UUID 失败后静默写入另一个 Collection。 |
| `backend/app/services/observability.py` | 仅补充受控计时名称，保证新增阶段可读，不放宽任意正文或密钥外发。 |
| `scripts/benchmark_bm25_write_payload.py` | 可重复的本地大规模父子结构 BM25 写入对照；使用独立临时 SQLite/WAL，结束删除，不接触生产资料。 |

SQLite 发布分别记录来源查询、STAGING、向量写入、写后验证、分词准备、SQL 替换、发布整体、全库计数和最终 commit。Chroma 分别记录 Collection 查询/创建、count、维度 query、add、get，附数值条数。计时是嵌套阶段，不能相加当作总耗时；异常继续沿用原有任务处理，不因计时失败改变业务结果。

没有合并跨文件事务，没有减少两阶段发布所需的持久化边界，没有删除写后校验，没有修改同步策略来掩盖写入成本。`kb.chunk_count` 继续按现有真实范围重计数，避免用可能失真的历史计数做增量推算。

## 大文件验证口径

主发布夹具以 2 MiB 合成原文，通过真实 `build_parent_child_chunks` 生成 32 个父块、1024 个子块，使用明确冻结的 parent=65536、child=2048、overlap=0 配置。这是为写入压力构造的合法配置，不宣称等于 ECS 当前参数。测试走实际 `publish_index_build`，检查父子关联、来源、BM25、ACTIVE 指针与失败恢复；向量服务替身只用于发布故障与 SQL 比较，不冒充真实供应商或 ECS I/O。

另有实际本地 Chroma 测试写入并完整回读 1100 个向量；2105 个向量的确定性调用契约检查覆盖多批次失败和句柄复用。父块只进入 SQL，不进入 BM25 或向量索引。未把普通切块测试结果当作父子模式结论。

## BM25 阶段实测

整份 2 MiB 父子发布对照中，来源查询由 **1056 次变为 3 次**，旧块 ORM 实体加载由 2112 个变为 0，新块按 500/500/56 三批写入；父块 32、子块/向量 1024，图关系、来源及逻辑结果一致。一次本地记录的发布时间为 3.519→2.556 秒，但不能由单次顺序样本宣称稳定提速。

尤其需要区分：**该完整发布样本的 WAL 增量是 1,326,640→1,334,880 字节，略有增加约 0.62%**。因此减少查询/ORM 开销并不等于减少整条链路的磁盘写入；下表只是在更大背景词汇表下单独测得的 BM25 阶段，不用它掩盖完整发布的结果。

可移植基线处理后的受影响单题复验，又记录到完整发布 WAL 1,330,760→1,318,400 字节、发布时间 2.527→2.031 秒。两次样本的 WAL 变化方向不同，更不能声称完整发布已有稳定磁盘写入收益；原始两份结果均保留。

夹具为 4,690,000 字节原文负载、120 个父块、1200 个子块、背景词汇表 50000 项；基线来自已有 ECS 源码快照，SHA256 `14e653b2cfa1e3e1d569e516858ff4afc9d49fe164e1cb795e3557160dfefc8b`。两个版本统计逻辑内容一致，父块没有进入 BM25。
