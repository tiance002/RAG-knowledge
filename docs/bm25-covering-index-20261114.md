# BM25 覆盖索引优化与 ECS 对照测试

2026-11-14。优化已应用到 ECS。只增加 SQLite 读取索引和对应的模型/启动迁移声明；没有修改 BM25 公式、词频、过滤条件、候选数量或排序规则，也未重建语料/向量。

## 问题证据与改动

线上实际源码是 postings 倒排实现，统计只读标量字段。成功的只读诊断显示，两道慢题的有效切片 count/sum 查询分别用了约 161 ms 和 2,004 ms；后一道的 postings 读取约 1 ms、评分约 0.013 ms。图片描述文件检查并非主因。第一道较早的 9 秒长尾没有在隔离诊断中复现，不将其全部归因于本次索引问题。

原计划按 KB 扫描 `chunk_index`，再逐条访问 `document_chunks` 和 `file_documents`。两个新增索引覆盖前两个表的筛选、关联和统计列，避免读取同一表里的大型 content/terms 数据页：

- `ix_chunk_index_bm25_live(kb_id, chunk_id, doc_length, id)`
- `ix_document_chunks_bm25_scope(id, file_id, chunk_type)`

本地模型为新数据库声明索引，幂等的 schema migration 为已有数据库补齐。ECS 采用精确两文件增量适配，排除了其他本地改动。在线维护在一个事务中创建两个索引；创建分别耗时 2,094.69 ms 和 3,733.51 ms，合计实际分配 23,130,112 字节（约 22.06 MiB）。API PID `630790` 未重启，其他服务未修改，数据行数、队列和 lease 状态保持一致。

改后线上查询计划对两个表均使用 COVERING INDEX，原 count/sum 完全一致。两个目标 KB 的完整前 50/1 个 BM25 候选 ID、顺序和分数与改前诊断一致。单次 SQL 诊断从约 160.66→19.71 ms、2,004.18→56.90 ms；这是局部诊断时间，不能代替端到端对照结果。

## 五题、每题三轮端到端对照

紧邻改动前采集三轮，创建索引后采集三轮，各 15 个请求。使用同一冻结五题、KB、请求参数和同一 API 进程，串行发送、无重试；Chroma 卸载/双路并行开关均保持 true，Chroma 单槽/HTTP 单次超时 30 秒。仅测试召回，不生成最终答案。

以下按每题三次客户端耗时的中位数计算，减少率为 `(基线中位数 - 改后中位数) / 基线中位数`。

| 题目 | 基线中位数 | 改后中位数 | 减少毫秒数 | 减少比例 |
|---|---:|---:|---:|---:|
| b5-013 | 400.67 | 342.40 | 58.28 | 14.54% |
| b7-013 | 401.48 | 333.87 | 67.61 | 16.84% |
| b1-024 | 364.66 | 269.46 | 95.20 | 26.11% |
| b1-030 | 508.07 | 453.57 | 54.51 | 10.73% |
| b6-024 | 357.53 | 348.00 | 9.53 | 2.66% |

全部请求算术平均值，分母各 15：**458.31→354.68 ms**，减少 **103.63 ms（22.61%）**。五个逐题中位数的均值则为 **406.48→349.46 ms**；两个指标分母及含义不同。

30/30 召回 HTTP 200、SUCCESS，所有命令和 journal 采集退出码 0，原始响应 SHA256 均核对通过，无跳过、重试、资源停止或健康探针失败。候选三轮 Top-10 ID/顺序和可用 BM25 分数均与基线第一轮一致；基线自身第三轮 b1-030 已有同集合不同顺序，不将这种已有波动当作索引引入的回归。原始缺失/null 分数保留区别；五题 Top-10 一致不等于整个数据集的正确性评测，b6 第二个 Gold 来源覆盖仍为 UNKNOWN。

每题只有三次样本，基线先于候选执行，缓存预热和时间顺序仍可影响结果。这里报告本次观测值，不将早先 9 秒等长尾与当前较快结果直接相减并当作优化收益。

单次配对并非全部降低：b6-024 第三轮为 341.112→342.725 ms，增加 1.613 ms（0.473%）；其三轮中位数仍降低 2.66%。客户端与服务端计时不同，表中统一使用客户端耗时；服务端 query_time 的全部 15 次均值为 450.39→346.88 ms（减少 22.98%），不混入客户端统计。

## 测试、资源与保留证据

本地 16 项相关测试通过，退出码 0、零错误/失败/跳过，包括迁移幂等、真实 SQLite 覆盖查询计划、精确评分/排序、删除/版本过滤以及 BM25 写入替换和父子迁移。原始日志保留已有的弃用警告。独立只读代码审查无阻断问题。

复用已有环境、冻结题集、数据库和 Chroma。只建立约 22 MiB 的两个新索引、小型源文件备份/发布记录和逐题日志；未复制数据库、语料或向量库。索引会增加今后写入和重建的维护成本，启动迁移首次创建索引时需要 SQLite 写锁。线上已在空闲维护窗口完成创建，无需下次启动重复构建。两轮测试资源保护均未触发，候选阶段可用内存最低 2,416,644,096 字节、磁盘最低 12,819,865,600 字节。

维护阶段可用磁盘由 12,867,055,616 变为 12,820,475,904 字节，净减少 46,579,712 字节；这是共享主机和 WAL 在该时间段的变化，不能全归因于本任务索引。API PID 630790/starttime 191208141 保持不变；CI 102,229/DC 117,507/files 23,787/已完成 receipts 11,778 均未变。

第一次完整诊断因临时写入保护阻止 jieba 初始化而没有执行 SQL；其退出码 0 与逐项失败状态不一致，该次作为失败证据保留。修正后只允许在专用目录写分词缓存，并对逐项失败返回非零退出码；成功诊断和测试均已核对逐项结果。诊断缓存和标记在进程退出后清理，原始错误/成功日志及冻结 Gold 保留。
