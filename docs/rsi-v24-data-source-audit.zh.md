## 来源边界、清点与已知限制

- 清点源路径和事件类型见 JSON 清单，所有 29 个源均为 metadata-only 检验并在当前 EventLog 规范下 `FULL_VALID`。零条事件的文件也在清单中。
- `task-model-budget.sqlite` 的 264 个请求对只是账本总数；它既包含不同角色，也不是专门的 RSI 子账本。不能把这些调用都计为 RSI 或 GLM40 改进，也不能把成本上界当作实际 invoice。
- `HOLDOUT_*` 是事件类型名，不表示本次审计打开过 holdout fixture 或答案。审计没有读取任何 Gold、封存题目、答案或证据文件正文；没有调用模型、API、ECS。
- 透明说明一次扫描边界错误：中间的递归扫描排除逻辑没有正确剪掉 `pytest-*` 目录，因此在所选历史根内对测试夹具 SQLite 执行了 schema、事件类型及 EventLog hash 链查询；事件 JSON 为计算 hash 在内存中解析，但没有输出或人工检查 payload/question/answer/evidence 文本。该扫描结果已弃用；最终报告仅纳入明确列出的 29 个历史非测试路径。未打开 QA300/QA500 闭合 holdout 根目录。
- 不对未记录的 actor、调用 epoch、人工身份、尾部完整性、模型实际采纳或隐藏问题/答案作推断。没有直接证据的身份字段和执行字段一律 `UNKNOWN`。
