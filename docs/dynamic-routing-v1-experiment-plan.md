## 三臂执行与调用上限

三臂使用相同题集、检索证据与冻结前文：CHEAP_ONLY 固定 Cheap；EXPENSIVE_ONLY 固定 Expensive；DYNAMIC 使用冻结规则，并只在既定确定性检查明确失败且策略允许时升级一次。贵模型对照覆盖全部计划槽位，不能继续仅接错题。

追问先使用已经保存的真实前文快照，三臂共享同一份；这样检验的是给定前文下的生成/路由。不得把不同臂生成的上一轮答案拼成可配对的“相同输入”。如果另测各臂自然延续的多轮轨迹，应单独定义会话级实验、记录不同历史，不混入本轮逐题配对。

最坏回答调用数为 12 Cheap + 12 Expensive + 24 Dynamic = **48 次**；本轮冻结前文可复用，额外前文与模型 Judge 调用均为 0。无证据/未授权/预算不足的槽位可不发送，但仍保留。48 是提案上界，不是授权额度或金额；执行前应按实际输入上限、输出上限、模型价格与额外推理 Token 计费方式估算并预留费用，费用未知不得按零计算。需要额外重试或无法复用前文时，应先更新独立调用预算，不能自动超出上界。

12 题验证完成并经负责人确认后，才考虑复用原 150 题与已有 30 追问扩大到 180 题；完整三臂最坏 720 次回答调用是后续可选规模，同样需要独立范围与费用批准，不是下一步默认任务。

在每个来源组内轮换三臂顺序，保存实际开始时间，避免固定先后顺序被当成模型延迟差异。并发、超时、限流处理固定并记录。UNKNOWN/已发送但未确认完成的调用先核查原账本；不能当成未花费的新请求直接重发。历史结果只有输入、模型配置、Provider、代码和度量口径全部匹配才允许显式复用，并单列复用数量；历史延迟不可混入当前服务性能结论。

## 判定与统计合同

不修改原 Gold 与评测规则。每题核心覆盖仍为 PASS / PARTIAL / FAIL / UNKNOWN；来源支持、引用、附加断言与合理拒答按已有口径独立记录。未校准自动初筛仅用于定位待复核记录，不得直接充当最终正确率或在线升级信号。结果以盲化模型身份的来源复核为准，保留争议与逐项证据。

每臂同时展示计划数、已观察数、缺失数、已复核数、UNKNOWN 数和四类覆盖计数。严格通过率 = PASS/(PASS+PARTIAL+FAIL)；确认通过/计划 = PASS/全部计划槽位。两者并列，UNKNOWN 不当 FAIL 也不从计划分母删除。执行状态、生成状态及 finish_reason 分别统计：Provider 故障、空回答、截断和 UNKNOWN 不由 HTTP200 或一次成功返回覆盖。

配对要求同 qid、同实验身份和同 `comparison_input_hash`（实际消息/证据/前文）。输出各臂缺题清单和 Hash 不符/缺失清单，再展示两两已知覆盖的胜/负/同级/无法比较数。同级仅表示 Gold 覆盖同级。来源组内问题相关，不能把每题当成独立随机样本推断总体显著性；本轮优先报告原始配对计数与按来源/格式/追问的分层结果。

每题 Token、费用与耗时必须累计该臂全部尝试，包括 Cheap 后升级、失败但已计费的尝试、可见推理 Token 和等待；另保留逐尝试明细。费用需要币种、价格版本与计费核对，任一应计费用未知时总费用 UNKNOWN。P50 使用有效耗时中位数，P95 使用 nearest-rank；同时展示有效 n 和缺失/无效 n。取消、超时或未观测终点不填 0；只对已观察终点的分位数不能解释为整体尾延迟。

只有完整三臂、匹配输入和完整同币种费用齐备后，才允许另行核算相对 EXPENSIVE_ONLY 的节费比例，并同时披露质量差值、升级率和 UNKNOWN 率。当前汇总入口始终将 `cost_savings` 留空，避免输出未经计费复核的节省声明。通过率不劣阈值、可接受成本/延迟门槛与发布验收需负责人事先确认；本方案不自行批准非劣效、延期或正式启用。
